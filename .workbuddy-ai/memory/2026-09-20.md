## FastBox TVBox 聚合搜索服务 — 开发与交付

### 项目目标
依据用户需求，结合参考项目（`dszz453/pansou-edge`、`dszz453/PanCheck`、`lampon/omnibox`、`Silent1566/OmniBox-Spider`）、本地《影视接口合集（五一特别版）.docx》以及 `pg.20260902-1029.zip`，构建支持 Docker 部署、TVBox 专用的极速全网资源搜索与豆瓣热播订阅系统。

### 架构与核心模块
- **极速并发引擎**：FastAPI + httpx + asyncio.gather，3.0s 全局熔断超时，TTL 双层内存缓存（热词二次查询 < 10ms）
- **三维资源矩阵**：网盘聚合搜（夸克/阿里/百度/迅雷/UC）+ 7 大免网盘 CDN 切片秒播站 + 本地托管 pg.jar 离线爬虫套件
- **PanCheck 死链秒检**：并发毫秒探活，自动过滤失效网盘链接
- **豆瓣热播首页**：实时抓取豆瓣热榜 + 内置 `/api/img` 防盗链海报反代，点击卡片自动触发全网聚合搜索
- **动态 Host 自适应**：`/tvbox?home=douban|lite|full`，自动适配局域网/公网域名

## 关键技术问题与结论

### 1. Windows 批处理中文编码陷阱
`.bat` 内含中文字符时，`cmd.exe` 默认 GBK 代码页会截断 `%errorlevel%`，报 `'evel'` / `'orlevel'` 错误。
**对策**：推送类脚本保持纯 ASCII，或改用 Python 驱动。

### 2. Docker Hub 命名规范
镜像名必须为 `<用户名>/<仓库名>:<tag>`，否则 push 会被拒绝（无权限）。本项目统一为 `zhangxiaonan1986/fastbox-tvbox:latest`。

### 3. 【重要】Hyper-V 虚拟机无法运行 Docker Desktop
**本机环境**：AMD Ryzen 7 PRO 4750U / Windows 10 专业版 19045 / Hyper-V 虚拟机

**诊断证据**（来自 `%LOCALAPPDATA%\Docker\log\host\com.docker.backend.exe.log`）：
```
engine linux/wsl failed to start: checking preconditions:
Virtual Machine Platform not enabled
No virtualization available
"hasNoVirtualization": true
"supportsVirtualization": false
```

**根因**：`Win32_Processor.SecondLevelAddressTranslationExtensions = False`
→ 宿主机未开启**嵌套虚拟化（Nested Virtualization）**，WSL2 引擎无法启动。

**三种解决方案**（详见 `DEPLOY-GUIDE.md`）：
- **A** 宿主机执行 `Set-VMProcessor -VMName "<VM>" -ExposeVirtualizationExtensions $true`（需关机重启虚拟机）+ 客户机启用 VirtualMachinePlatform/WSL 组件
- **B** GitHub Actions 云端构建推送（推荐，免本地 Docker，自动双架构）——工作流已内置
- **C** 借用 NAS / 另一台有 Docker 的设备构建

### 4. Docker Desktop 安装路径（本机）
用户级安装，非 Program Files：
`%LOCALAPPDATA%\Programs\DockerDesktop\resources\bin\docker.exe`
（安装过程中会短暂出现在 `DockerDesktop.staging\`，脚本需每轮重新解析路径）
